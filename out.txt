gemini-cli -i ./resources/diagram.png -p "explain me this image"

The above command has below code flow:

Parse the input parameters passed to the command (`argparse` in `cli.py`).
Check if required parameters (`--prompt` or `--input`) are present.

A prompt (`-p`) can be a string or a path to a file.
If it's a file path, read the content from the file (`read_file` in `cli.py`).

A filter (`-f`) is a string used to filter files when the input (`-i`) is a folder.

Input (`-i`) can be a local file or a local folder.
Supported input file formats and extensions are defined in `FILE_FORMATS` in `utils.py`.
    - image: png, jpg, jpeg, gif
    - text: txt, csv, json, xml, html, java, cpp, py
    - pdf: pdf
    - video: mp4, avi, mov
    - audio: mp3, wav, flac
Input files have a size limit (`MAX_FILE_SIZE` in `utils.py`, currently 20MB).
    - If input is a file:
        - Validate the file path and size (`validate_file_path`, `validate_file_size` in `utils.py`).
        - Determine file type (`get_file_type` in `utils.py`).
        - Check if the model supports the input file type (using `model_capabilities['inputs']` in `api_interface.py`).
        - Call the appropriate API function (`send_file_prompt` in `gemini_api.py`).
    - If input is a folder:
        - Validate the folder path (`validate_folder_path` in `utils.py`).
        - Get files from the folder, applying the filter if provided (`get_files_from_folder` in `utils.py`).
        - Process the *first* supported file found (current logic in `api_interface.py`).
        - Check if the model supports the file type.
        - Call the appropriate API function (`send_file_prompt` in `gemini_api.py`).

Output path (`-o`) is optional, with different behavior for text vs non-text outputs:
    - For text output:
        - Always printed to the console
        - Only saved to file if `-o` is explicitly provided
    - For non-text outputs (images, etc.):
        - Always saved to a file
        - If `-o` is not provided, generate a filename automatically:
          `<first-four-words-of-prompt-kebab-case>_<model_name>_<timestamp>.<extension>` (`generate_output_filename` in `cli.py`).
        - The extension depends on the `output_type` (e.g., `.jpg` for image).

Output type (`-t`) is optional.
    - If `-t` is provided (e.g., `text`, `image`), validate if the selected model supports this output type (using `model_capabilities['outputs']` in `cli.py`).
    - If `-t` is *not* provided:
        - Infer the output type from the selected model's default (`model_capabilities['default_output']` in `cli.py`).

Model selection (`-m`) uses aliases defined in `MODEL_MAP` in `cli.py`.
    - If `-m` is not provided, use the `DEFAULT_MODEL_ALIAS` (`default`).
    - If `-m` is provided, look up the alias in `MODEL_MAP` to get the actual model name and its capabilities (inputs, outputs, default_output).
    - If the alias is not found, show an error message and exit.
    - The `MODEL_MAP` structure now includes capabilities:
        ```python
        MODEL_MAP = {
            "flash": {
                "name": "gemini-2.0-flash",
                "inputs": ["text", "image", "audio", "video", "pdf", "file"],
                "outputs": ["text"],
                "default_output": "text"
            },
            "pro": {
                "name": "gemini-2.5-pro-exp-03-25",
                "inputs": ["text", "image", "audio", "video", "pdf", "file"],
                "outputs": ["text"],
                "default_output": "text"
            },
            "imagen": {
                "name": "imagen-3.0-generate-002",
                "inputs": ["text"],
                "outputs": ["image"],
                "default_output": "image"
            },
            # ... other models ...
            "default": { # Default maps to flash
                "name": "gemini-1.5-flash-latest",
                "inputs": ["text", "image", "audio", "video", "pdf", "file"],
                "outputs": ["text"],
                "default_output": "text"
            }
        }
        ```

API Interaction (`interact_with_gemini_api` in `api_interface.py`):
    - Initializes `GeminiAPI` client.
    - Determines the API call based on model capabilities and inputs.
    - Handles image-generation-only models (like Imagen) separately.
    - Calls `gemini_api.send_text_prompt` or `gemini_api.send_file_prompt`.
    - Returns the response data (text string or image bytes).

Output Handling (in `cli.py`):
    - Detects if the output is text or binary using `isinstance(response_data, bytes)` check
    - For text output:
        - Always printed to console regardless of whether -o is specified
        - Only saved to a file if `-o` flag is provided
    - For binary outputs (images, etc.):
        - Always saved to a file
        - Determines the output path (user-provided or generated)
        - Creates the output directory if it doesn't exist
        - Writes the response data to the file in binary mode ('wb')

Error Handling:
    - Checks for API key (`GEMINI_API_KEY` environment variable).
    - Handles file/folder not found errors.
    - Handles unsupported model aliases or output types.
    - Catches exceptions during API calls or file writing and logs errors.
    - Uses `sys.exit(0)` for clean exits, `parser.exit(1)` or `sys.exit(1)` for error exits.
